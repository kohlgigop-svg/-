# 质检人员质量评估工具

面向数据标注项目的**质检质量评估工具**：输入总体样本量、抽样量与混淆矩阵，自动输出指标点估计、置信区间、召回率警戒线、各指标观察线，并调用大模型生成根因分析与动作建议。

纯前端静态页面，无需后端。数据保存在浏览器本机（localStorage），可导出备份。

**在线地址**：https://kohlgigop-svg.github.io/-/

---

## 一、设计立场（先读这一节）

本工具的目标是**让质量问题显形**，不是评价质检人员。

指标体系回答的是「哪里可能有问题、根因在哪、该做什么」，**不回答「这个人行不行」**。理由有三条，均为可核算的事实：

1. **标准自身有噪声** — 金标准若来自二审，二审的一致率就构成指标天花板。尺子会抖，量不出人的高矮。
2. **任务构成不同则不可横比** — 专判难例与专判简单批的人天然不同分。横向绝对比较等于惩罚承担难例的人。
3. **样本量支撑不住** — 当实际应驳回样本只有 10 条时，召回率的 95% 置信区间宽度可达 **45 个百分点**。用这样的估计给人定性，不是严格，是不严谨。

因此工具内置三条禁令，并写入 AI 提示词的硬性纪律：

- 不许用本指标单独评价个人能力或排名
- 不许在小样本（区间无法收窄）时作任何评价
- 不许把本指标与个人奖惩直接挂钩

> 指标与个人奖惩直接挂钩会立刻诱发指标操纵：压低驳回量即可让精确率好看，同时把风险全部转移给下游。这不是道德问题，是激励设计问题。

## 二、功能

| 功能 | 说明 |
|---|---|
| 指标计算 | 准确率、精确率、召回率、特异度、NPV、FPR、FNR、F0.5、F1、F2 |
| 置信区间 | 比例型指标用 **Wilson 区间**；F 族用**参数 Bootstrap**（固定种子，结果可复现） |
| 结构量 | 实际应驳回率 π、质检驳回率 τ、净偏离 Δ=τ−π（区分「行为问题」与「能力问题」的判据） |
| 警戒线 | 召回率下限 R_min，由基线 B 与容忍率 T 推导，并换算为**可容忍漏判条数** |
| 观察线 | 各指标前 k 次统计的中位数；连续两次低于才提示纳入观察 |
| 三层诊断 | 结构层 → 行为层 → 可靠性层，输出确定性结论（不交给模型自由发挥） |
| AI 分析 | DeepSeek 生成根因假设、动作建议（含优先级/责任/时限/依据）、需人工确认项 |
| 记忆 | 以项目名分组保存历史，自动用于警戒线与观察线计算 |
| 数据管理 | 项目新建/重命名/删除、按项目或全量导入导出（JSON） |

## 三、计算方法

### 3.1 方向约定

**正例 = 驳回（坏数据）**，负例 = 通过（好数据）。换方向会使召回率与精确率的含义互换。

### 3.2 指标

| 指标 | 公式 | 分母 | 管什么 |
|---|---|---|---|
| 准确率 Acc | (TP+TN)/N | 抽样总数 | 整体协调性；π 偏离均衡时被稀释，**不作主指标** |
| 精确率 P | TP/(TP+FP) | 质检驳回数 | 驳得准不准（**会被 π 稀释**） |
| 召回率 R | TP/(TP+FN) | 实际应驳回数 | 漏没漏（关联不可逆风险） |
| 特异度 Spec | TN/(TN+FP) | 实际合格数 | 冤没冤（**衡量误判只能用这个，不能用 P 代替**） |
| Fβ | (1+β²)·P·R / (β²·P + R) | — | P、R 的加权调和平均，权重比 = **β²** |

**β 的权重关系**：β=2 表示召回率权重是精确率的 **4 倍**（β²），不是 2 倍。

**精确率被 π 稀释的实测值**（固定特异度 99%、召回率 90%）：

| 实际错误率 π | 1% | 5% | 20% | 50% |
|---|---|---|---|---|
| 精确率 P | **47.6%** | 82.6% | 95.7% | 98.9% |

同一个质检员、同样的判定能力，P 随 π 从 47.6% 变到 98.9%。**解读 P 必须同时报 π。**

### 3.3 置信区间

**比例型指标用 Wilson 区间**，不用 Wald。Wald 在 n=100、k=0 时给出 `[0, 0]`，等于宣称漏判率精确为 0；Wilson 给出 `[0, 3.7%]`，才反映真实不确定性。

**F 族指标用参数 Bootstrap**。F1 是 P 与 R 的非线性组合且二者由同一个 TP 决定（负相关），分别求区间再代入会丢掉相关性。Bootstrap 使用固定种子，同一份数据每次得到完全一致的区间，保证可复核。

**n 是各指标自己的分母**，不是抽样总量。同一个抽样集合里 P 与 R 的 n 可能相差一个数量级——这就是「P 不稳」与「R 不稳」是两个不同的病。

### 3.4 警戒线（只对召回率设置）

1. 基线 **B** = 前三次评估的实际驳回率中的最高值（不足三次取全部；无历史则取本次）
2. 容忍率 **T** = 1 − 需求方要求的验收准确率
3. 召回率下限 **R_min** = 1 − T/B；若 R_min ≤ 0（即 B ≤ T），退化为历史最差召回率
4. 可容忍漏判条数 = max(1, 实际应驳回数 × (1 − R_min))

**闭环验证**（单元测试覆盖）：按 R_min 恰好执行时，回代准确率恰好等于验收要求。例：π=8%、验收 95% → T=5% → R_min=37.5% → 可容忍漏判 50 条（分母 80 条）。

判定用**置信区间下限**：下限 ≥ R_min 判为达标；区间跨越 R_min 判为不确定；区间上限低于 R_min 判为确证问题。

> **为什么只给召回率设绝对警戒线**：漏判通常不可逆（坏数据流向模型训练或下游决策）；精确率属返修成本，只在效率维度作相对比较。

### 3.5 观察线

各指标取前 k 次统计的中位数（k 默认 3，可调）。不足 k 次取现有全部值的中位数并标注稳健性有限。**连续两次低于观察线**才提示纳入观察，单次低于不作结论。

### 3.6 分层抽样

点估计仍用抽样内的真实计数：P、R、F1 等为比值，加权前后取值相同。同时报告有效样本量：

```
n_eff(经典) = (Σw)² / Σw²        w = 1/入样概率
n_eff(FPC)  = 计入有限总体校正 (1−f)
```

过采样「已驳回层」可提高该层精度，但总体层面的有效信息量会被折算，报告时应同时给出有效样本量。

## 四、使用方式

1. 打开页面 → **新建项目**（项目名用于分组保存历史）
2. 填入评估周期、总体样本量、抽样量、混淆矩阵
3. 点 **计算** → 查看指标矩阵、警戒线推导、预判诊断
4. 点 **保存为记录** → 历史数据自动用于下一次的警戒线与观察线
5. （可选）在 **设置** 中填入 API Key → 点 **生成分析** 获得 AI 根因分析与动作建议

### API Key 说明

工具为纯前端页面，**API Key 保存在你本机浏览器的 localStorage**，不写入代码、不上传任何服务器。仓库源码中不含任何 Key。

首次使用需自行填入（设置 → API Key → 填 `sk-...` → 测试连接）。

> 若要多人共用且不希望各自填 Key，需改用服务端代理方式（如 Cloudflare Worker），不要在公开仓库中嵌入 Key。

## 七、边界与不适用场景

- 适用于**二分类**（通过/驳回）且有金标准的场景
- **不适用多分类**质检（如通过/驳回/返修），需扩展为宏平均或微平均
- **不适用无金标准**场景，此时应改用一致性指标（Cohen's κ、Krippendorff's α）
- 分母为 0 的指标一律显示「不可计算」，**不以 0 冒充**
- 准确率在分层抽样改变类别构成时不代表总体
